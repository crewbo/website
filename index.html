01 · How it works

Each agent knows what the others are working on.

In a team project, usually one person drives the agent while everyone else waits, or every agent edits the same files and the team finds out at merge time. With Crewbo, everyone runs their own agent, on their own machine and operating system, on the same repository.

Claims, checked before every edit

When an agent starts on a file, it holds a claim on it. A small daemon on each computer answers the agent's own hooks, so another agent that tries to edit the file is stopped and told who has it.

Your crew, next to the code

The crew panel shows each teammate, whether they are online, and what their agent is doing. A file a teammate holds says so at the end of its first line.

Handoffs, not collisions

Need a file someone else holds? Ask for it. They get Hand off and Not yet, and the lead can step in. Two agents wanting the same file is a handoff, not an error.

Conflicts before anyone merges

Teammates' tasks are checked against each other with git, so two branches that change the same lines show up as a conflict before the merge, with the files named.

03 · Open source

Your code never leaves your computer.

Crewbo never sends the contents of your files anywhere, and it sends no telemetry. Code moves only through your own git remote. Your team runs its own sync server, and the code is open source.

What your sync server sees

  • Your GitHub login, computer name and OS
  • File paths and how long a claim lasts
  • Task text, branch names and commit ids
  • Which agent is working, and on which file
  • Who is online in the room

What never leaves your computer

  • The contents of your files
  • Your device's private key
  • Task worktrees and run logs
  • Usage data: there is none

04 · Install

Set up in about 15 minutes.

You need git 2.38 or later, one agent (Claude Code, Codex or Antigravity) and a GitHub account. The first release is planned for about 22 November 2026; until then, build Crewbo from source.

1. The crewbo command

Until the first release, with Go and Task:

git clone https://github.com/crewbo/crewbo
cd crewbo
task build
bin/crewbo daemon

2. The editor extension

The crew panel, claims and handoffs in VS Code and editors built on it. With the first release it comes to the Visual Studio Marketplace and Open VSX; until then, install the .vsix you build with task ext:package.

3. Or the Crewbo IDE preview

An editor with Crewbo built in and the crew panel open from the first start, for Linux, macOS and Windows, with the first release. It uses Open VSX, so extensions only Microsoft publishes are not available.

05 · Questions

Questions

What is Crewbo?

A coordination layer for teams whose coding agents work on the same repository at the same time. A daemon on each computer enforces file claims through each agent's own hooks, a small sync server shares who holds what, and conflicts between teammates' branches show up before anyone merges.

Does Crewbo see my code?

No. Only paths, task text, branch names, the agent's name and who is online leave your computer, and only to your team's own sync server. The privacy page lists every field.

Which agents does it work with?

Claude Code, Codex and Antigravity. The checks also run when you prompt Claude Code or Codex from their own VS Code extensions.

Do I need the Crewbo IDE?

No. The extension for VS Code and the crewbo command are the main way to use Crewbo. The Crewbo IDE is a preview for teams that want everything in one download.

What is the sync server?

A small server one person on the team runs (crewbo serve). It passes claims, tasks and presence between teammates' daemons. It never receives file contents.

Is Crewbo open source?

Yes. Crewbo is Apache-2.0; the sync server is AGPL-3.0. The source is on GitHub.
